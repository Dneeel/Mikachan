# Follow: user controls and provider status

`/follow instagram|twitter|youtube|tiktok HANDLE` or `/follow PROFILE_URL` opens an owner-bound confirmation and configuration panel; `/following` lists monitored accounts. Public events are checked about once every 15 minutes while the bot is running. Existing subscriptions remain in SQLite when access is temporarily suspended. New follows default to all **implemented** event categories, although sources may report unavailability.

Each new event notification has exactly two buttons: **⬇️ Get it** and **🔗 View original**. The first invokes the on-demand downloader for a post, stores and sends the text snapshot for bio/name updates, or fetches the **current** profile photo for avatar updates; live-start notifications can link to a live stream, but cannot promise an entire live video file. The second button opens the specific post/story/live, or the account profile on a profile change. Buttons are owned by the numeric user and saved in SQLite. The previous auto-media mode is migrated to notify-on-demand.

Instagram Posts/Reels are queried from independent `/posts/` and `/reels/` gallery-dl extractors, alongside best-effort `/stories/<handle>/` metadata. Instagram can require login even for public material; operator-owned Netscape cookie files are opt-in via `MIKACHAN_INSTAGRAM_COOKIES_FILE`. Profile card, Latest Post, Latest Reel and Stories controls use public sources and explicitly report failures.

X/Twitter uses FxTwitter and bounded gallery-dl fallback to read public posts; full text can be independently retrieved for text-only tweets, and text accompanies available media. YouTube uses its public feed for standard videos, flat listings for Shorts, and verified `is_live` metadata on the Streams listing for experimental live-start notices. YouTube public name/bio/avatar fields are best effort. TikTok checks posts, best-effort stories, structured profile data and experimental live sessions. Rotating signed CDN URLs are not used as reliable avatar-change identifiers.

A blocked source does not silently mark itself healthy or reset its category baseline. Source failures are tracked in `follow_source_errors` and shown after manual **Check now**. Tests cover two-button notices, isolated category baselines, independent Reels, Live status verification, SQLite migration and source errors.

**Not implemented or not guaranteed:** Instagram/X live signals; reliable username changes for all four platforms; guaranteed Instagram/TikTok Stories; guaranteed near-real-time detection (polling interval and API restrictions). Do not infer that “public” implies anonymous API access. See [the repair dossier](FOLLOW_DOWNLOADER_REPAIR_FA.md) for deployment and tests.
