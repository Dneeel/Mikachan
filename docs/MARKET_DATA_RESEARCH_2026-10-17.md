# Iranian market data review — 2026-10-17

## Decision and scope

`دلار`, `سکه`, `ارز`, `طلا`, `تتر`, and `بیت‌کوین` are exact, authorized Utilities inputs in the existing aiogram bot. `/rate USD|EUR|AED|SEKE|GOLD18|USDT|BTC IRT` uses the same service. It reports indicative Toman quotes by source, actual last-trade time where directly available, and **fetch time** separately. It does not call the downloader or create another update consumer. Official IRR reference pairs are refused with a clear explanation; the older `/rate USD EUR` and BTC/ETH global pairs remain separate.

The implemented no-key relay is [Gheymat's documented public API](https://gheymat.online/price-api), queried on demand per asset for provider-tagged rows, cached for 600 seconds, and limited to **200 calls/UTC day in SQLite** against its published 250/day free allowance. Concurrent requests for the same asset share one call. Named source quote values are validated for asset, IRT unit, plausible spread, and finite positive amounts. Their midpoint median is shown only if at least two sources agree within 5%; otherwise individual source values are shown without a consensus figure. Quote sides are presented as a range because the relay's `buy_price`/`sell_price` direction was not independently established. During a 2026-10-17 read-only probe, its USD rows differed across TGJU, Navasan, AlanChand and Bonbast. Its `created_at` was recent even while a separate TGJU-derived dataset showed Thursday's cash-market observation, so `created_at` is **not** displayed as trade time.

For USDT and BTC, [Wallex's official public market API](https://api-docs.wallex.ir/) supplies a **direct TMN bid/ask order book and timestamped last trade**. These are cached 30 seconds and displayed separately from relayed Nobitex, Bitpin, Tetherland and Tabdeal rows; a relayed Wallex row is excluded to avoid counting the same exchange twice. Direct crypto output still works if Gheymat is unavailable. A configurable [Navasan direct API](https://www.navasan.tech/api/webserviceguide/) adapter parses `usd_buy`, `usd_sell`, `eur`, `aed_sell`, `sekkeh`, and `18ayar` plus each item's Unix observation time. It uses HTTPS, suppresses credential-bearing errors, and replaces the relayed Navasan row when recent and within 10% of other providers. Quotes over two hours old are shown with their age and excluded from the median. **No owner API key is present, so this adapter is mock-tested but not live-verified.** The default 8-hour refresh is conservative for Navasan's 120-call/month free plan; paid plans may set a shorter `NAVASAN_REFRESH_SECONDS` after quota review.

## The proposed spreadsheet formula

The supplied `IMPORTXML("https://alanchand.com/", "/html/body/main/section[5]/div[2]/div[1]/div/div/div[2]/span[1]/text()")` selected a **USDT/Tether card** when checked on 2026-10-17, not cash USD. That position depends on page layout and can change. Ten nested `SUBSTITUTE`s convert Persian digits only; Arabic digits, separators, locale-specific decimal marks, error pages, buy/sell direction, and timestamps remain unresolved. AlanChand has an [official JSON API](https://alanchand.com/media/api) with currency/gold/crypto categories and a bearer token. Use that when licensed access is available; do not treat an internal web AJAX endpoint as a public contract. Its [robots.txt](https://alanchand.com/robots.txt) disallows `/get-all-data`.

### Free-page `IMPORTXML` trial, not a bot feed

The live homepage HTML confirms a more stable manual-sheet selector for cash USD: `//tr[@title='قیمت دلار آمریکا']/td[contains(@class,'buyPrice')]/text()` and the analogous `sellPrice` cell. The page also prints a Persian last-update string. Both cells currently use Persian numerals and comma grouping, so conversion must remove grouping and normalize digits before numeric calculations. A sheet should import both quote sides and the visible update label, keep the source name, and reject empty or unparsable cells. Even this semantic XPath can break when the site changes markup, and a successful Google fetch does not prove the site's price was freshly observed.

Two other public pages returned static HTML during the probe: [TGJU's dollar page](https://www.tgju.org/profile/price_dollar_rl) and [Bonbast's homepage](https://www.bon-bast.com/). TGJU's visible `l-price_dollar_rl` value was **2,638,000 rial** while Bonbast explicitly showed **264,200 Toman** for the same asset class; copying both into a median without TGJU's `/10` normalization yields a false comparison. Bonbast exposed a site-level `Last Update` string and separate Sell/Buy columns, but its [official programmatic API](https://www.bon-bast.com/docs) is paid. The sites' public robots files do not grant reuse rights or a stability promise. Google [documents `IMPORTXML`](https://support.google.com/docs/answer/3093342?hl=en) as importing XML/HTML with XPath, not as a market-data API or real-time feed. Sheet recalculation, request blocking, DOM revisions, unit differences, quote-side mismatches, holidays, and missing source observation times make a multi-site scrape unsuitable as the production price source. A manually inspected sheet is useful for side-by-side validation and discovering provider discrepancies.

The unfiltered Gheymat endpoint was also probed: it returned a compact 161 KiB aggregate containing only its own `GHEYMAT` summary row for USD, EUR, AED, SEKE, GOLD18, USDT, and BTC. The per-asset filtered endpoint returned named third-party rows, so one unfiltered request cannot replace the current filtered calls without losing the comparison evidence.

Recent [muchToman](https://github.com/doxigo/muchToman/blob/main/DEVELOPMENT.md) is a useful engineering reference: separate fiat and crypto source chains, named sources in every response, plausibility checks, and dropping unverified conversions. Its source mapping notes that Bonbast quotes JPY/AMD per 10 and IQD per 100 while TGJU uses per-unit values. [developerAmira's Telegram project](https://github.com/developerAmira/telegram-bot) likewise documents multi-source checks, unit normalization, provider health, and visibly stale fallback. These patterns are candidates for a later approved enhancement; their scraping and fallback sources must be checked for permission and precision before reuse. Small one-source bots and synthetic USDT-to-cash conversions are not evidence of accuracy.

## Best production path after provider access

1. Keep cash USD, bank transfer, USDT, physical coin, 18K gold per gram, and global crypto as **different asset types**. Store an explicit `price_unit`, `unit_size`, source, quote side, source observation time, fetch time, and market state for every quote. Convert IRR to Toman once using a documented unit; never use Google's official IRR midpoint as open-market cash USD.
2. Obtain a licensed direct Iranian market feed, starting with a real Navasan key for its documented per-item timestamps and explicit `usd_buy`/`usd_sell` or `sekkeh` codes. Run a real 7-day comparison trial against a second licensed feed such as AlanChand or Bonbast, spanning market hours, Friday/holiday closures, and provider outages. Compare observations at the same time; don't average unknown quote sides.
3. For crypto in Toman, keep the integrated direct Wallex pair and add a second direct licensed exchange only after confirming symbol units, timestamps and redistribution terms. Keep CoinGecko/global USD reference rates separate. Avoid fabricating a local crypto price by multiplying global USD by a stale cash dollar rate.
4. Use **source** observation time when available, not merely the time of an API fetch. If all valid sources fail, return an error or a clearly aged last-known quote. Drop implausible assets instead of zero-filling. Record source health without exposing keys. Cache with single-flight concurrency and provider quotas, as the current read path does.

The current public API integration is suitable for a small private bot's **indicative** quotes. It is not a verified high-frequency trading feed. The owner approved the additional assets and multi-source comparison in the follow-up task. Completing live cash-market timestamp verification requires an owner-provided direct-feed key or subscription.

## Non-downloader review

The single dispatcher still authorizes numeric user and group IDs before exact text, commands, or callbacks. Persian rate triggers are exact, so ordinary messages stay silent. Community cultural commands depend on an owner-reviewed, rights-cleared corpus; they do not fabricate jokes or poetry. Utilities process media on demand within bounded file/image sizes and two concurrent CPU-heavy slots; OCR language inspection and animated-sticker rendering now use those slots without blocking the event loop. Translation remains explicitly configured and external; a stronger privacy disclosure and provider health check can be considered before widening use. Terminal management was subsequently implemented on v2. Live provider and Telegram acceptance remain separate.
