# Follow provider investigation · 2026-10-20

This records reproducible observations, not a promise of universal monitoring. A successful post download proves only that a known URL is accessible. Follow must discover unknown new IDs repeatedly, which is a different provider operation.

## Safe operating rule

Each selected Follow category must keep its own source health and baseline. Empty or failed data from a previously populated timeline is an outage, not proof that posts were deleted. Cached profile data requires a freshness check. Notifications must link to a verified public item or state clearly that a category could not be checked. A 100% detection guarantee is not supportable through anonymous extraction or a third-party Telegram bot. Authorized platform sessions or official provider access can improve coverage, but require owner configuration and live tests for each platform and account type.

Mikachan accepts optional owner-managed `MIKACHAN_TIKTOK_FOLLOW_COOKIES_FILE` and `MIKACHAN_X_FOLLOW_COOKIES_FILE` for Follow extractors only. Each must be a private file owned by the bot service user. The installer panel can edit these paths; it does not create platform sessions. The existing `MIKACHAN_INSTAGRAM_COOKIES_FILE` serves Instagram extraction. Cookies can expire or be challenged, so these settings improve access only when verified by a live check.

## Additional live probes · 2026-10-20

For the reported Instagram account `mehrdad.balagar`, the public HTML profile page returned HTTP 200 and a matching `og:title` plus `og:image`. Its unkeyed web profile JSON endpoint returned HTTP 401 with `require_login: true`; the older `?__a=1` endpoint returned HTTP 201 with no content. The HTML did not include a usable timeline or biography. Mikachan now uses that page only as an identity-checked fallback for the display name and a stable avatar filename, never as evidence that posts, reels, stories, or biography were checked. On the owner's VPS, these responses must be probed again because platform anti-bot rules vary by IP.

The upstream [gallery-dl Instagram report #9777](https://github.com/mikf/gallery-dl/issues/9777) documents different access results by category on the same account: posts and reels worked while avatar/highlights failed. [#7292](https://github.com/mikf/gallery-dl/issues/7292) documents a 401/login redirect. These examples support independent health per category and explain why one successful Instagram action must not mark Follow as fully functional.

For `Dniuis`, FxTwitter's statuses endpoint returned HTTP 403 behind a challenge. The public X profile page returned HTML without an extractable timeline. The Twitter syndication profile widget returned HTTP 200 but its `timeline.entries` was empty. VxTwitter exposed a matching profile only from a stale cache, so the two-hour freshness rule rejected it as a change signal. None of these responses proves there were no new tweets. The existing gallery-dl timeline can be retried with a private owner-controlled X cookie file; [twscrape](https://github.com/vladkens/twscrape) and [x2t](https://github.com/TheMRVX/x2t) likewise depend on authenticated or guest GraphQL sessions whose behavior changes and requires per-account live verification.

For TikTok, Atmosphere's profile endpoint returned a matching identity and profile fields, while its public statuses endpoint returned HTTP 500 in the same environment. This is why profile change checks can be healthy while post checks are unavailable. Stories and live endpoints cannot be inferred from a working profile endpoint. The existing gallery-dl/yt-dlp extractors remain category-specific and may require an authorized TikTok session.

The reported `@instaRoxinoBot` demonstrates reliable **on-demand** media access for some profiles, but its 29-second spacing, no stable story URL in each returned item, and no provider completion marker for stories make it unsuitable as an unverified background Follow feed. A safe Follow source must provide stable item IDs, publication times or ordering, exact creator identity, and a measurable freshness limit. Without those, a bot can silently miss events or invent alerts. No publicly tested, free source found in this investigation meets those requirements for every requested event on Instagram, X, TikTok, and YouTube. This is a source-access limit, not a polling frequency issue.
