# Follow provider investigation · 2026-10-20

This records reproducible observations, not a promise of universal monitoring. A successful post download proves only that a known URL is accessible. Follow must discover unknown new IDs repeatedly, which is a different provider operation.

| Platform | Checked source and result | Engineering implication |
| --- | --- | --- |
| Instagram | [gallery-dl's current site matrix](https://github.com/mikf/gallery-dl/blob/master/docs/supportedsites.md) lists posts, reels, stories and profiles with cookies. [Instaloader's CLI docs](https://github.com/instaloader/instaloader/blob/master/docs/cli-options.rst) explicitly require login for stories. The recent [Icarus scraper](https://github.com/DangerousPotato08/Icarus-Instagram-Scraper) wraps Instaloader and uses authenticated sessions; it does not provide a new anonymous story source. | The Telegram provider can supply on-demand media, but its 29-second query spacing and batch downloads make it a poor 15-minute polling backend for many follows. Reliable arbitrary-account stories/live cannot be certified without an appropriately authorized Instagram source. |
| TikTok | The public Atmosphere profile endpoint returned HTTP 200 and structured identity, name, bio and avatar for `bnetanyahu`; its statuses endpoint returned HTTP 500 in the same probe. [TikTokApi](https://github.com/davidteather/TikTok-Api) uses a browser and an owner's `ms_token`; [gallery-dl's matrix](https://github.com/mikf/gallery-dl/blob/master/docs/supportedsites.md) marks stories as cookie dependent. | An identity-checked profile fallback was added for name/bio/avatar. Posts still use existing sources. Stories and live remain best effort; a successful profile response does not prove their health. |
| X | FxTwitter profile and statuses requests returned HTTP 403 from this environment. VxTwitter returned a matching public profile, but its `fetched_on` timestamp was about 37 hours old; using it for change alerts would be wrong. The recent [x2t](https://github.com/TheMRVX/x2t) uses guest GraphQL, cookies when needed, FxTwitter, yt-dlp and syndication. Its AGPL-3.0 code was studied as an architectural reference and was not copied into Mikachan. [twscrape](https://github.com/vladkens/twscrape) uses accounts and rotation. | A VxTwitter profile fallback is allowed only when its snapshot is at most two hours old and the handle matches. Text, photo and video tweets share one verified timeline category; if the timeline endpoint is blocked, known post URLs may still download while Follow cannot discover them. |
| YouTube | The existing channel Atom feed is a lightweight upload source; yt-dlp checks Shorts and current live state separately. The feed alone does not certify that a stream is live. | Keep independent video, Short and live health. Do not mark a source healthy from an unrelated successful category. |

## Safe operating rule

Each selected Follow category must keep its own source health and baseline. Empty or failed data from a previously populated timeline is an outage, not proof that posts were deleted. Cached profile data requires a freshness check. Notifications must link to a verified public item or state clearly that a category could not be checked. A 100% detection guarantee is not supportable through anonymous extraction or a third-party Telegram bot. Authorized platform sessions or official provider access can improve coverage, but require owner configuration and live tests for each platform and account type.

Mikachan accepts optional owner-managed `MIKACHAN_TIKTOK_FOLLOW_COOKIES_FILE` and `MIKACHAN_X_FOLLOW_COOKIES_FILE` for Follow extractors only. Each must be a private file owned by the bot service user. The installer panel can edit these paths; it does not create platform sessions. The existing `MIKACHAN_INSTAGRAM_COOKIES_FILE` serves Instagram extraction. Cookies can expire or be challenged, so these settings improve access only when verified by a live check.
