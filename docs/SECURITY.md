# Security and privacy

- Startup requires a positive numeric Owner ID, bot token and numeric environment seed containing the Owner. On first unified startup, existing SQLite `access` and `allowed_groups` rows migrate additively to named role and group registries. The protected primary Owner ID is stored in SQLite. Later Telegram edits persist independently of the seed; a changed primary Owner must come from the authenticated VPS manager.
- Effective roles are OWNER, ADMIN and USER with ACTIVE, SUSPENDED and REVOKED status. Only active Owners have incoming private service. Other active people may interact only inside approved groups. An approved group's membership and Telegram-native Administrator badge grant no Mikachan role. Group admins require an explicit Owner assignment for the particular group. Every callback and command rechecks current numeric permissions; suspension and revocation cancel queued jobs and running tasks at the settings boundary. Follow subscriptions are removed when their owner or group is no longer authorized at the next monitor pass.
- A primary Owner can neither be demoted nor revoked through Telegram. Secondary Owner promotion or revocation needs a time-limited primary-Owner request plus independently authenticated VPS manager approval. The manager stops the service and saves a consistent SQLite snapshot before changing the role. An additional Owner cannot initiate a further Owner promotion. Changing the primary Owner in the manager also saves a snapshot and transfers protected status.
- Global module switches stop new requests; existing downloader jobs drain, and Follow polling pauses. Group switches can narrow but cannot override a globally disabled feature. Admin changes are audited. The terminal's `PRIVATE_CHATS_ONLY` value is retained for legacy configuration compatibility; unified role and group policy decides actual access.
- `/groupstatus` records only received Telegram message metadata, a category, forwarding flag and minimal known-member labels. It never downloads media for counting. Exact events are retained for 400 days and older counts are rolled into Tehran-local monthly aggregates. It excludes service messages, edits and Mikachan's own outgoing messages. Telegram Privacy Mode and bot visibility determine coverage; these statistics cannot recover earlier Telegram history. Ban listings cover only actions recorded by Mikachan, not a complete Telegram banned-member list.
- User nicknames affect presentation only and are stored per group. Group personal settings menus are publicly visible in that group even though callbacks are user-bound. Do not enter sensitive secrets in group menus. Outbound private notification delivery may require a person to have initiated a private Telegram conversation; such a message does not grant incoming private commands.
- Media utilities limit input to 8 MiB and images to 20 MP. TGS rendering runs in a bounded child process; local OCR uses Tesseract. Translation text is sent only on an explicit request to the configured HTTPS provider or to the unkeyed public endpoint when no provider is configured.
- URL submission performs syntax checks and host classification without remote requests. No, expired, unauthorized and repeated callbacks cannot create a job. Links in ordinary authorized noncommand text are the only unsolicited processing trigger.
- Fetch-time DNS checks reject private and mixed answers, but HTTP proxy resolution and yt-dlp's internally discovered redirects/media URLs can bypass the local DNS check. **The extractor and proxied direct downloader therefore still carry SSRF risk.** Run the bot under an unprivileged user with restrictive egress on a dedicated host/container before accepting untrusted users.
- Direct downloads are streamed with a 48 MiB public or 1900 MiB local limit. Local Bot API mode requires loopback URL and API credentials. Child processes use argument arrays and their own process group; cancellation targets the owned task.
- `.env` is ignored by Git and must be private. Tokens, provider keys and the optional CoinPJ user session must not be logged. SQLite and job directories belong to the service user. No private account scraping or DRM bypass is intended.
- `USERBOT_SESSION` is a full Telegram account credential. Keep it only in protected server configuration; never send it to the bot or commit it. `USERBOT_STAGING_CHAT_ID`, when explicitly set, must name a private chat controlled by the operator. For on-demand media relay without that setting, the user account creates a private supergroup containing only itself and the verified Mikachan bot, grants the bot minimal admin visibility, and records its ID in SQLite. Temporary staged messages are deleted after copying; the group persists for reuse. `/url` and `/edit` send selected media to third-party bots only when an authorized user explicitly invokes them. Third-party media availability is outside Mikachan's control.
- Optional Instagram and YouTube cookies must be Netscape-format files outside the repository, owned by the bot user with mode 0600. Set `MIKACHAN_INSTAGRAM_COOKIES_FILE` or `MIKACHAN_YOUTUBE_COOKIES_FILE` in the manager. Each path is used only for its provider. The platforms may still rate-limit or reject the session.
