# پنل ترمینال جدید Mikachan V2

## مشخصات

- طراحی تک‌ستونه، بدون Sidebar، بدون Grid یا پنل وب، بدون وابستگی Textual.
- هدر با **همان ASCII Art فایل `ascii-art.txt`** که داخل `deploy/manager_ui.py` جاسازی شده و نیازی به فایل خارجی در سرور ندارد.
- ترمینال عریض (حدود ۱۴۰ ستون و ۲۶ سطر یا بیشتر): نمایش کامل ASCII Art. ترمینال کوچک‌تر: نسخه فشرده؛ در صفحه‌های بسیار کوچک: عنوان متنی.
- فلش بالا/پایین: جابه‌جایی؛ Enter: انتخاب؛ Esc/Left: بازگشت؛ Q: خروج؛ R: Refresh؛ Backspace: پاک‌کردن حرف؛ Ctrl+U: پاک‌کردن مقدار فیلد.
- همه عملیات واقعی همچنان در `deploy/manager.py` انجام می‌شوند؛ فایل‌های Telegram bot، Follow، Downloader و CoinPJ بدون تغییر باقی مانده‌اند.

## منوها

1. Bot & Health — سرویس، شروع/توقف/راه‌اندازی مجدد، وضعیت، صف، لاگ و تشخیص عیب.
2. Releases & Updates — فهرست شاخه‌های vN، انتخاب شاخه، تغییر Commit، آپدیت، Rollback، پاک‌سازی Release.
3. Backups & Recovery — بکاپ، انتخاب بکاپ از فهرست، Restore، ذخیره‌سازی، Recovery، پاک‌سازی مدیای نیمه‌تمام.
4. Settings & Access — Setup، گروه‌های تنظیمات، وضعیت درخواست‌های Co-owner و تأیید نهایی روی VPS.
5. Host & Maintenance — پیش‌نیازها، نصب اولیه، حذف کد، حذف کامل پروژه.
6. Exit.

## اصلاحات

- ورود اطلاعات مرحله‌به‌مرحله: Enter فقط مرحله فعلی را ثبت می‌کند و به بعدی می‌رود؛ پرش ناخواسته بین فیلدهای چندگانه حذف شده است.
- انتخاب نسخه و Snapshot از روی فهرست انجام می‌شود؛ نیازی به تایپ دستی Snapshot ID نیست.
- تمامی حذف‌های خطرناک و Rollback نیازمند عبارت تأیید دقیق‌اند؛ متن هشدار توضیح می‌دهد Rollback داده‌های جدید را کنار می‌گذارد.
- مخفی‌سازی BOT_TOKEN، Session، API Key و Proxy دارای مشخصات اتصال در رابط مدیریت و خروجی config.
- عملیات طولانی در Thread مستقل اجرا می‌شوند و رخداد پیشرفت به حلقه UI منتقل می‌شود؛ خروج ناخواسته حین عملیات جاری مسدود است.
- شکستن خطوط گزارش بلند و اسکرول با فلش‌ها؛ مدیریت اندازه‌های مختلف ترمینال.
- رفع مشکل توالی‌های Esc و عدم خروج در منوی اصلی هنگام استفاده از کلیدهای فلش در برخی شبیه‌سازهای SSH.

## نصب امن روی VPS

این ZIP روی VPS یا GitHub به‌صورت خودکار اعمال نشده است. **اول از فایل‌های فعال و تنظیمات و دیتابیس بکاپ بگیرید.**

بهترین روش: تغییرات `deploy/manager_ui.py`، `deploy/manager.py`، `deploy/manager-requirements.txt`، مستندات و تست را در شاخه `v2` ثبت و سپس با ابزار مدیریت خود پروژه Update کنید. بعد از فعال‌سازی نسخه جدید، تابع `_refresh_panel` فایل‌های پنل پایدار را به‌روزرسانی می‌کند و بار بعدی دستور `mikachan` رابط جدید را باز می‌کند. اگر شاخه فعال نسخه قدیمی داشته باشد، Update ممکن است نسخه قدیمی پنل را برگرداند.

برای تست مستقل بدون دسترسی به Telegram روی checkout:

```bash
PYTHONPATH=.:src python3 -m deploy.manager_ui
PYTHONPATH=.:src pytest -q tests/test_manager_ui.py
```

اجرای مدیریت با دسترسی root یا `sudo mikachan` فقط روی VPS واقعی و مدیریت‌شده انجام شود. از دو سرویس هم‌زمان با Bot Token یکسان جلوگیری کنید.

## محدودهٔ تضمین

تست‌های محلی شامل منطق منو و تست تعاملی واقعی با PTY هستند؛ اما نصب واقعی systemd، Git fetch، تغییر نسخه در VPS و بازیابی پایگاه داده در سرور اصلی در این محیط آزمایش نشده‌اند. «بکاپ» در Manager کنونی Snapshot دیتابیس و تنظیمات است، نه آرشیو مستقل همه فایل‌های پروژه. Rollback کنونی کد + داده را باز می‌گرداند و نسخهٔ Code-only مستقل ندارد.
